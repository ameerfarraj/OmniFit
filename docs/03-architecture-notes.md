# ארכיטקטורה, הערות פיתוח ותכנון עתידי

## 1. שיטת עבודה הנדסית
* **ארכיטקטורת 3-Tier:** החלוקה תתבצע לשכבת תצוגה (UI עם תבניות כמו MVVM), שכבת לוגיקה עסקית (BLL בשרת עבור אלגוריתמים וסליקה), ושכבת גישה לנתונים (DAL מול מסד הנתונים)[cite: 1].
* **עבודה איטרטיבית (Agile):** פיתוח מודולרי (למשל: סיום מודול משתמשים והרשאות, ורק אז מעבר למודול תזונה)[cite: 1].
* **תכנון Bottom-Up:** העבודה תתחיל מתכנון סכמת בסיס הנתונים (ERD) כדי להבטיח יציבות השכבות שמעליה[cite: 1].

## 2. אינטגרציות AI ומנועי המלצות
* **ניתוח סרטוני טכניקה:** יתבצע באופן מקומי (On-Device) באמצעות מודלים מוכנים להערכת מנח גוף (כגון Google MediaPipe), תוך שימוש בלוגיקה מתמטית פשוטה לחישוב זוויות (למשל זיהוי זווית הברך בסקוואט)[cite: 1]. ה-AI מזהה מיקום, והקוד מגדיר את חוקי הפיזיקה והכושר[cite: 1].
* **מנוע המלצות (Rule-Based):** המלצות תזונה ואימונים יתבססו בשלב הראשון על מערכת מבוססת-חוקים המצליבה יעדים (כמו BMR ו-PR) עם מסד הנתונים בעזרת עצי החלטה ושאילתות פשוטות, ללא צורך במודל למידת מכונה מורכב[cite: 1]. 

## 3. ניהול גרסאות ושרידות API
* **API Versioning:** כל נקודות הקצה (Endpoints) בשרת יכללו קידומת גרסה מפורשת (כמו `/api/v1/users`)[cite: 1]. בעת שחרור עדכונים, השרת יתמוך במספר גרסאות במקביל כדי למנוע קריסה של אפליקציות בטלפונים שלא עודכנו דרך החנות[cite: 1].

## 4. תכנון עתידי (Backlog - V1.1 / V1.2)
* **מרקטפלייס עצמאי:** פלטפורמה שתאפשר למאמנים למכור מוצרים פיזיים או דיגיטליים ישירות דרך האפליקציה[cite: 1].
* **פיד וידאו קצר (Workout Reels):** אזור גילוי מבוסס גלילה אינסופית המוקדש לסרטוני אימון (פורמט 9:16)[cite: 1].
* **תיוג מוצרים בסרטונים (Shoppable Videos):** המערכת תאפשר למאמנים לתייג מוצרים מאמזון ישירות על גבי הסרטון כדי לאפשר רכישה מהירה מבלי לעזוב את הפיד[cite: 1].
