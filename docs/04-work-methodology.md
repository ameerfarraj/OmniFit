\# שיטת עבודה וסדר פיתוח (Work Methodology)



כדי להבטיח פיתוח יעיל, יציב ומהיר של OmniFit, אנחנו לא עובדים בשיטת מפל המים (Waterfall) הנהוגה באקדמיה (כלומר: לא משרטטים תרשים UML מפלצתי של כל המערכת לפני שניגשים לקוד). 

במקום זאת, אנו עובדים בגישת \*\*Agile (פיתוח איטרטיבי)\*\* ובארכיטקטורת \*\*3-Tier\*\* בגישת \*\*Bottom-Up\*\*.



\## מחזור פיתוח של מודול בודד

המערכת מחולקת למודולים עצמאיים (למשל: משתמשים והרשאות, מנוע תזונה, מנוע אימונים). על כל מודול נעבוד לפי הסדר הבא, ורק כשנסיים אותו – נעבור למודול הבא:



1\. \*\*מיני-שרטוט ERD (Bottom-Up):\*\* 

&#x20;  לא מתחילים מה-UI! מתחילים משרטוט טבלאות מסד הנתונים הספציפיות הנדרשות לאותו מודול והקשרים ביניהן. אם בסיס הנתונים לא יציב, כל השכבות מעליו יקרסו.



2\. \*\*שכבת הגישה לנתונים (DAL - Data Access Layer):\*\*

&#x20;  מעבר ל-C# ו-Visual Studio. כתיבת המחלקות המייצגות את הטבלאות, תוך שימוש ב-Entity Framework כדי לייצר את מסד הנתונים מהקוד (Code-First).



3\. \*\*שכבת הלוגיקה העסקית (BLL - Business Logic Layer):\*\*

&#x20;  פיתוח האלגוריתמים והשירותים של המודול (למשל: פונקציית חישוב BMR, מנגנון עומס יסף, או הצפנת סיסמאות).



4\. \*\*שכבת התצוגה והשירות (Presentation / API Layer):\*\*

&#x20;  פתיחת נקודות קצה (Controllers/Endpoints) שמקבלות בקשות HTTP מהאפליקציה (הקליינט) ומחזירות תשובות מסודרות בפורמט JSON.



5\. \*\*בדיקה ונעילה:\*\*

&#x20;  מוודאים שהמודול מתפקד מקצה לקצה. ננעל – ועוברים לאפיין ולפתח את המודול הבא.
